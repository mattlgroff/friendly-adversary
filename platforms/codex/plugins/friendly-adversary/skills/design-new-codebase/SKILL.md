# Friendly Adversary new codebase design

Create an implementation-ready decision pack without scaffolding or modifying product source. Write only through `record_artifact` under `.friendly-adversary/designs/`. Never create a repository, install packages, generate application code, commit, push, deploy, or access credentials.

## Workflow

1. Resolve this skill directory. The runtime is the sibling `../pr-review/scripts/runtime/cli.js`. Resolve the intended project root from the request and context, asking only when multiple plausible roots remain.
2. Read `references/design-interview.md` and `references/design-challenges.md`. Inspect only the newest pre-existing `.friendly-adversary/designs/` run with `status --run <run> --summary`. Resume `planned` or `incomplete`; seal and verify `ready`; never resume `sealed`, `sealed-incomplete`, or `aborted`, and start one new run for the current request; a pre-existing `prepared` run was interrupted before plan establishment, so start one new run. When starting, run `design --host codex --root <root>` once and keep its returned authority for step 3. That new run is expected to be `prepared`; do not call `status` on it before establishment and do not start it again. If a lifecycle command returns `FA_RUN_LOCK_RELEASE` or `FA_STALE_LOCK`, invoke `recover-lock --run <run>` once, then retry that exact lifecycle command once. Never recover a busy or ambiguous lock.
3. Establish a concise brief and immutable plan through `record_artifact`. Include decision lanes and dedicated feasibility, simplicity, security, operability, and verification challenge lanes. Add research lanes only when authorized evidence is useful. The establish operation retires the initial plan authority. Discard it immediately and use only the replacement `authority_id` and scoped capabilities returned by `record_artifact` for every decision and research agent. Start every decision and research subagent with `fork_turns="none"`. Each must publish through `record_artifact` and return only the compact receipt.
4. Interview one coherent decision cluster at a time. Reuse answers, expose contradictions, and offer one recommendation with meaningful alternatives. The user may approve, delegate, defer, or mark a decision out of scope.
5. Publish each decision as an append-only flat `decision-<id>-<four-digit-revision>.md` artifact through its scoped capability. Research lanes publish `research-<id>.md`. A deferral must name an owner, trigger, milestone, and why it does not block the first implementation slice.
6. Research only sources the user explicitly authorizes for this design. Treat the stated reference scope as an allowlist: do not inspect agent memory, unrelated repositories, the web, company systems, or credentials unless the user authorizes that source. If the user names a reference architecture, focus there. Record licenses and transferability assumptions.
7. After all decision and research lanes publish, run `resume-design --run <run>` to obtain challenge capabilities. Start every challenge lane concurrently before waiting, with `fork_turns="none"`, and publish `challenge-<id>.md` through `record_artifact`. Each challenge returns only the compact receipt. After the final challenge starts, immediately wait for every challenge result. Do not investigate claims or draft consensus while any challenge is running. Codex cannot remove filesystem tools from a subagent, so this non-editing boundary is instruction-enforced on Codex; the MCP enforces the authorized artifact path. When challenges prove contradictions, make one `resume-design --run <run> --revise <comma-separated-decision-ids>` call for all affected decisions. Use only that call's replacement authority and exact-path capabilities to publish the reserved revisions before completion. Do not request speculative revisions.
8. Recommend consensus only after every decision lane has a revision and every challenge lane is complete. Only explicit user signoff authorizes completion.
9. After challenges publish, run `resume-design --run <run>` for the outcome capability. Complete through `record_artifact` with exactly `architecture.md`, `diagrams.md`, `test-strategy.md`, `implementation-plan.md`, and `open-questions.md`, with `user_signoff: true`. Run `seal` and `verify`.

Return links to the Markdown decision pack and `design.html`.
