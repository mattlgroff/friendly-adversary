# Friendly Adversary codebase audit

Audit a trusted brownfield repository without editing or executing it. Write only through `record_artifact` under `.friendly-adversary/audits/`. Never run repository-owned tests, builds, typechecks, scripts, binaries, executable configuration, package managers, or installed project tools.

1. Read `references/audit-inventory.md`, `references/finding-contract.md`, and `references/audit-adjudication.md`. When the inventory includes tests, test infrastructure, or behavior whose proof depends on tests, also read `references/lenses/verification.md` and apply its test-oracle requirements.
2. Inspect only the newest pre-existing `.friendly-adversary/audits/` run with `node "${CLAUDE_PLUGIN_ROOT}/skills/pr-review/scripts/runtime/cli.js" status --run <run> --summary`. Resume `planned` or `incomplete`; seal and verify `ready`; never resume `sealed`, `sealed-incomplete`, or `aborted`, and start one new run for the current request; a pre-existing `prepared` run was interrupted before plan establishment, so start one new run. When starting, run `node "${CLAUDE_PLUGIN_ROOT}/skills/pr-review/scripts/runtime/cli.js" audit --host claude-code --repo <repo>` once and keep its returned authority for establishment in step 3. Any successful JSON result containing `run_directory` is sufficient authority output: never rerun that audit command because the host later summarizes, hides, or loses conversational access to its output. That new run is expected to be `prepared`; do not call `status` on it before establishment and do not start it again. Analyze only `snapshot-files/`, never live repository paths. If a lifecycle command returns `FA_RUN_LOCK_RELEASE` or `FA_STALE_LOCK`, invoke `recover-lock --run <run>` once, then retry that exact lifecycle command once. Never recover a busy or ambiguous lock.
3. Infer the complete semantic subsystem inventory. Classify a path as generated only when a canonical source or generator mapping is declared. Treat unmapped host-specific manifests, MCP launch configuration, skill entry points, and invocation metadata as canonical production contracts with exactly one authoritative owner. In `inventory.md`, reconcile total, canonical, related, excluded, unowned, and overlapping path counts; list paths only when unowned or overlapping counts are nonzero. Never dump `snapshot.json`, receipts, the whole file index, or the whole artifact tree into context. Query machine evidence narrowly and use bounded indexes plus selected files. Establish the immutable non-overlapping subsystem lane manifest through `record_artifact`. The establish operation retires the initial plan authority. Discard it immediately and use only the replacement `authority_id` and scoped capabilities returned by `record_artifact` for every subsystem agent.
4. Start every `audit-subsystem` agent concurrently. Each receives only its boundary, relevant dimensions, pinned evidence, the exact `references/finding-contract.md`, exact flat filename `subsystem-<id>.md`, and capability. Include the exact verification lens text for every subsystem that owns tests or relies on tests as proof. It preflights, self-validates against the finding contract, publishes through `record_artifact`, and returns only a receipt. After the final subsystem starts, immediately wait for every subsystem result. Do not inspect the snapshot, deterministic evidence, or partial reports while any subsystem is running.
5. Stop incomplete for missing lanes or narrowed full-repository coverage. Continue safe coverage after critical findings.
6. After all subsystem reports publish, run `resume-audit --run <run>` for the outcome capability. Independently check inventory coverage and cross-subsystem contracts while adjudicating proven findings, evidence-backed risks, rejected candidates, and gaps. Do not create a remediation roadmap.
7. Complete with `adjudication.md` and `report.md`, then run `seal` and `verify`.

Return the prioritized verdict and paths to `report.md` and `report.html`.
