# Knip integration

Knip 6.34.0 is bundled with Oxc parser 0.147.0 and resolver 11.24.2 WASM
bindings. No native analyzer, runtime download, npm command, additional MCP
tool, or additional lens is needed. Node 22.22 or newer remains required.

## Applicability

- Codebase audit: run for package-based JavaScript/TypeScript project roots,
  including frontend packages in mixed Python repositories.
- PR review: run for package/lockfile/configuration changes, source-file
  additions or deletions, and import/export/require edits. Ordinary function
  implementation and documentation edits do not automatically run Knip.
- Analyze the complete package graph, not only changed files. Parent/lens
  adjudication must establish whether a PR introduced a finding; a changed-line
  filter alone misses unchanged code orphaned by deleting its last consumer.

## Evidence and execution

The ordinary deterministic collector stores untouched native JSON in
`deterministic/knip*/stdout.json`, stderr, version, command, exit status, and
duration alongside it. `coverage.json` preserves Knip configuration/tag hints
and workspace/plugin metadata separately. Configuration hints, malformed
output, missing metadata, timeouts, and loader failures make the required
analysis incomplete. Findings use Knip exit code 1; operational failures do
not become clean results.

No fix flags are accepted by the internal launcher. Caching and the Nx daemon
are disabled. PR configuration runs in the same trusted repository-code
boundary as the existing project checks, with the existing mutation check.
Audits retain their source-only snapshot boundary: executable JS/TS tooling
configuration is not evaluated. Such projects receive an explicit incomplete
result rather than installing dependencies, executing snapshot code, or silently
disabling plugins. Data-only configuration and ordinary source analysis work
without installing target dependencies. Missing generated code or dependencies
can still limit coverage. No configuration or ignore files are automatically
added to the reviewed project.

## Build and verification

The engine is generated by `scripts/build-knip.mjs`. The pinned build-only
dependency tree and integrity hashes are in `engines/knip/build/package-lock.json`.
Run `npm ci --ignore-scripts --omit=optional --force` in that directory, then
`npm run build:knip` at the repository root. `--force` permits npm to unpack
explicit WASM packages whose CPU field is wasm32 on a native build host.
It does not enable native bindings. Ordinary users never run this build step.

The Oxc parser needs emnapi 2.0.0-alpha.4; its published alpha.3 pin conflicts
with wasm-runtime 1.2.3's peer range. The resolver retains wasm-runtime 1.1.6
and emnapi 1.x. These versions are pinned separately and exercised together.
The visitor's lazy local require is made statically bundleable. The upstream
WASM binaries are not rebuilt. Runtime files, hashes, and package license
inventory live in `engines/knip/runtime/` and are synchronized to both plugins.

Licenses, supplemental notices, source provenance, and the conservative Rust
dependency inventory are in [Knip attribution](../engines/knip/NOTICE.md).
They are included in both plugin copies alongside the runtime.

Native Windows and Linux execution and broader upstream parity remain
unverified for this new integration. Local macOS tests alone are not
cross-platform certification.
